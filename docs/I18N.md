# 国际化与 YAML 目录

> 本文区分 `0.1.0-dev` 当前实现与后续质量目标。目录声明为 stable/preview 只表示仓库 manifest 状态，不代表已完成所有终端和人工语言评审。

## 1. 当前目录状态

`locales/manifest.yml` 当前列出：

- stable：`en-US`、`zh-CN`；
- preview：`zh-TW`、`ja-JP`、`ko-KR`、`es-ES`、`fr-FR`、`de-DE`、`pt-BR`、`ru-RU`；
- planned：`it-IT`、`pl-PL`、`tr-TR`、`uk-UA`、`id-ID`、`vi-VN`、`th-TH`、`hi-IN`、`ar`、`he-IL`、`fa-IR`。

只有仓库中实际存在并进入生成 registry 的目录能被内置加载。preview 目录允许缺少消息，并逐 key 回退；不能宣传为完整翻译。planned 目录没有内置 catalog。

当前主 TUI、页面/表头、帮助、状态信息和 Inspector 标签已大范围使用 message ID。内核/provider 的原始字段、status/quality/reason 和部分诊断文本仍保持技术英文标识，i18n 覆盖尚未完成。

## 2. 源码与运行时结构

```text
locales/
  manifest.yml
  _template.yml
  en-US.yml
  zh-CN.yml
  ...
src/wtop/i18n/
  init.lua
  catalog.lua
  format.lua
  locale.lua
  plural.lua
  user_catalogs.lua
  yaml_profile.lua
src/wtop/generated/locales/
  registry.lua
  en-US.lua
  zh-CN.lua
  ...
```

`locales/*.yml` 是内置翻译的人类可编辑权威源；`src/wtop/generated/locales/*.lua` 是确定性构建产物，不应手工编辑。bundle 中的内置目录使用生成 Lua 模块，启动时不重新解析内置 YAML。

## 3. Catalog schema

```yaml
_meta:
  locale: "en-US"
  name: "English (United States)"
  direction: "ltr"
  fallback:
    - "en"
  plural_rule: "en"
  catalog_version: 1

messages:
  app.title: "wtop"
  tabs.overview: "Overview"
  process.count:
    one: "{count} process"
    other: "{count} processes"
```

当前受限 YAML profile 与 catalog 校验包括：

- UTF-8 单文档；只接受受限 mapping/sequence/scalar；
- 禁止 anchors、aliases、merge key、自定义 tag 和重复 key；
- 根只接受 `_meta`、`messages`，并拒绝未知 `_meta` 字段；
- catalog `_meta.locale` 与 fallback locale 必须是规范化 BCP 47 形式，message ID
  使用小写点分路径；
- 文本参数使用 `{name}`，同一复数消息各分支的占位符必须一致；
- plural category 必须被对应规则允许，并包含该规则要求的分支；
- stable 内置目录必须与 `en-US` 完整兼容；preview 可以缺失，但已有同名消息的结构和占位符必须兼容。

Parser 不是通用 YAML 执行环境，不会构造对象或执行 tag。

## 4. 构建

```bash
make locales

.tools/lua-5.5.1/bin/lua tools/compile_locales.lua \
  --source locales \
  --output src/wtop/generated/locales \
  --check
```

编译器校验 manifest/catalog 一致性，按 locale 和 message ID 确定性生成 Lua 模块，写入源 SHA-256、catalog version 和 generator version，并生成使用字面量 `require` 的 registry。`--check` 比较预期输出与已提交生成物。

当前编译门禁不包含人工语言评审、截图比对、伪语言扩张或运行于多种终端的 RTL 测试；这些属于发布流程待办。

## 5. 用户 XDG catalog

TUI 启动时自动扫描：

```text
$XDG_CONFIG_HOME/wtop/locales/*.yml
```

未设置 `XDG_CONFIG_HOME` 时使用 `~/.config/wtop/locales/*.yml`。当前边界为最多 64 个候选文件、每个最多 1 MiB；文件名必须安全且以 `.yml` 结尾。目录不存在是正常的 absent 状态。

用户 catalog 通过与内置目录相同的 parser/schema 和 `en-US` 兼容性校验，但允许不完整。文件按名称排序加载；重复 locale、危险文件名、读取失败、过大或校验失败会被分别记录，其他安全文件继续加载。TUI 当前只在底部状态区显示加载数量/错误数量或首个失败原因，没有 catalog 管理页面或完整错误列表。

用户 catalog 不进入 onedir/onefile payload，也不会修改仓库内置 registry。它可以覆盖同 locale 的内置 catalog；缺失 key 仍沿 fallback chain 查找。

CLI 与主配置并不要求请求 tag 已存在于内置 registry：它们先做 locale 语法校验与
规范化，合法的未知 tag 仍可进入 TUI。translator 创建后，用户 catalog 加载会重建
原请求的 fallback chain，所以 `$XDG_CONFIG_HOME/wtop/locales/*.yml` 可以为该 tag
提供实际翻译。`--snapshot` 和 `--diagnose` 不创建 translator，也不扫描用户目录。

## 6. 语言选择与回退

请求语言的优先级是：

```text
--lang > config locale > LC_ALL > LC_MESSAGES > LANG > en-US
```

标准化示例：

```text
zh_CN.UTF-8 → zh-CN
pt_BR       → pt-BR
```

规范化包含 `_`/大小写与常见环境 suffix 处理；空 subtag、非法字符、重复 variant/
extension、缺 extension value 等语法错误会由 `--lang` 或 config 校验拒绝。合法但
未知的规范 tag 不会在 CLI 阶段被当作拼写错误；若 TUI 加载后仍没有对应用户或
内置 catalog，才按父 tag/alias 和 `en-US` 回退。用户 catalog 的 `_meta.locale`
必须直接使用规范形式，不能依赖加载时替它改写。

Translator 先解析最匹配的已加载 catalog，再按 catalog 的 `_meta.fallback` 递归回退，最后加入 `en-US`。例如当前 `zh-TW` 链为 `zh-TW → zh-CN → en-US`。回退逐 message ID 进行；一次缺失 lookup 返回 ID 并进入内部 diagnostics 计数，不会使整个 TUI 退出。

Translator API 能返回 requested/active locale、方向、回退链、覆盖率、缺失量和格式错误等 diagnostics；当前 Insights 页和 `--diagnose` 尚未完整展示这组信息。

## 7. 复数与格式

当前实现包含一组内置 plural rule，支持 `zero`、`one`、`two`、`few`、`many`、`other` 中各语言需要的子集。formatter 提供：

- locale-aware 小数点和分组（当前只为部分语言定义约定）；
- SI/IEC bytes、bit/s、frequency、duration、percent、Celsius/Fahrenheit；
- 命名占位符插值。

这不是完整 CLDR/ICU 实现：没有日期时间/时区格式、货币、排序、复杂 message format、测量系统自动选择或所有 locale 的本地数字符号。部分 TUI 文本仍直接组合技术字段。

## 8. Unicode 与 RTL 边界

renderer 以 cell 宽度处理 UTF-8、CJK、组合字符、emoji 和 variation selector，并优先使用原生 `wcwidth`。真实终端的宽度表差异仍可能导致个别错位。

Catalog schema 接受 `_meta.direction: "rtl"`，Translator 也能返回方向；但当前 Workspace、table、按键和 renderer 没有使用该值进行镜像、bidi isolation 或 shaping。仓库也没有内置 RTL catalog。因此 RTL 当前仅是可表达的元数据，不是已支持的 UI 能力，不能通过反转字符串来冒充实现。

## 9. 发布前剩余门禁

- 清除核心可见文本中的硬编码 fallback 和未本地化 provider reason，或明确技术字段例外。
- 为 stable 目录建立维护者与人工评审记录，并验证占位符语境而不只验证结构。
- 增加长文本/伪语言和多尺寸截图或 golden 回归；当前仓库没有 `_pseudo.yml`。
- 在声明 RTL 支持前实现方向布局、bidi/shaping 策略和终端矩阵。
- 给用户 catalog 提供可访问的详细错误报告和覆盖/回退 diagnostics。
- 明确 stable 覆盖率、截图尺寸与 promotion 流程，并让 CI 真实执行这些门禁。
