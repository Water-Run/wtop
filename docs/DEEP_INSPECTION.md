# 深度检查：当前实现与边界

本文档只描述当前的 `0.1.0` 实现。wtop 的长期方向是把常用的只读诊断信息集中到一个 TUI 中，但它目前还不能完全替代 `smartctl`、`perf`、`systemctl`、`ss` 或各厂商专用的 GPU 工具。

## 1. 当前的入口

每个检查器（Inspector）的进入方式都相同。按下对应按键会调用检查器的 `enumerate` 步骤，随后 wtop 要么打开选择器，要么直接读取单个实体：

- **没有可检查的实体** —— 覆盖层说明原因，并带上 `enumerate` 返回的具体缘由；
- **恰好一个实体** —— 立即检查，不弹出选择器；
- **多于一个实体** —— 由选择器列出，最多 256 条，超出部分会注明截断。

传给 `inspect` 的实体始终是 `enumerate` 产出之一。因此，某个检查器如果开始列出多个服务或内存控制器，就会自然获得选择器，而不需要新增任何界面；只有一个服务的主机则保持原有行为。选择器是共用的：实体不具备的列留空，而不是猜测填充，所以 PMU 行和磁盘行可以出现在同一个选择器里。

默认注册表有五个按需检查器：

| 按键 | 检查器 | 当前数据源 |
| --- | --- | --- |
| `s` | SMART / NVMe | `/sys/class/block` + 可选 `smartctl` |
| `b` | 系统内存带宽 | PMU sysfs 描述 + 可选 `perf stat`/`sleep` |
| `d` | systemd unit；Workloads 中直达所选 unit | 可选 `systemctl list-units` / `show` |
| `D` | `sshd` 服务与监听端口 | 可选 `systemctl` + 进程快照 + `/proc/net/tcp*` |
| `u` | logind 登录会话 | 可选 `loginctl list-sessions` / `show-session` |

结果显示在一个可滚动的文本覆盖层中。覆盖层支持方向键、`PageUp`/`PageDown`、`Home`/`End` 和鼠标滚轮；用 `Esc`、`Enter` 或 `q` 关闭。标量值会显示其质量（quality），字节、带宽、百分比、温度、时长等常用单位会被格式化。选定的集合字段内联显示最多 128 条，并标注剩余条数。字段来源、时间戳和原因细节目前不会完全展开。systemd 详情可以跳到主进程或控制组，登录会话可进入对应的 scope unit。固定到仪表盘、检查器历史与插件界面仍是后续工作。

独立的 `h` 传感器覆盖层在 Linux、macOS 和 Windows 上读取最新的共享快照。它最多显示 256 个通道，展示平台提供时的最近采样值、质量、附加读数和阈值。它随共享快照的更新而刷新，不启动独立的硬件探测。打开期间，即使传感器控件放不进当前页面，它也会让共享传感器采集器按前台节奏运行；关闭后恢复页面原本的采集节奏。如果最近一次传感器采样已经超过 15 秒，覆盖层会将其标注为过期（stale）。

所有外部辅助程序都通过不经 shell 的 argv Runner 调用，并带有超时、输出大小、固定环境和进程清理约束。`--safe-mode` 会禁用 Runner，因此检查器中依赖外部命令的部分将不可用；普通的 procfs/sysfs 采集器继续工作。

### systemd unit

`d` 列出系统管理器和当前有效用户管理器中的已加载 unit，包括非活动项。
最多采集 1024 项，在管理器间分配预算；选择器最多显示 256 项。`/` 搜索
完整的有界清单，支持名称和描述的字面条件、`manager:system` / `manager:user`
及 `type:service` 等类型条件。先筛选再应用显示上限，`Esc` 逐级结束编辑、
清除查询和返回。Workloads 中所选节点有明确 unit 名称时，`d` 直接打开其详情。

详情只读取公开白名单：加载/活动状态、可用时的主 PID、重启/退出结果、
当前内存/累计 CPU 时间/任务数、配置的资源上限、控制组和 unit 文件路径。
没有读数的计数保持未知，明确的无限上限显示“不限”。配置上限不替代
Workloads 页按内核控制组读取的实际限制。启动探测不执行 `systemctl`；
按键时才调用，每次最多 750 ms 和 256 KiB，安全模式不执行调用。

系统和用户管理器有独立身份；用户查询仅连接 `/run/user/<有效 UID>`，
root 会话不借用 sudo 调用者的用户总线。来自 Workloads 的查询还要求
`ControlGroup` 与所选路径相同，同名但位于其他管理器或容器的 unit 不被合并。

详情的 `p` 在核对进程启动时间和当前 cgroup 后打开主进程；进程样本尚未
到达时只请求一次采样，退出或 PID 复用不会转到另一进程。`Esc` 可返回 unit。
`g` 跳到其控制组并展开祖先，`r` 重新读取。`l` 查看该 unit 的近期 journal，
`Esc` 从日志逐级返回列表和 unit。登录会话可从 `u` 查看；完整依赖图及服务启动、停止或配置修改
仍未接入。

### unit journal

日志读取仅在 unit 详情按 `l` 或日志中按 `r` 时执行，不参加普通刷新。
查询核对 unit 的管理器、名称与来源控制组，按当前内核启动 ID 和准确的 unit
名称过滤，默认最多 100 条、512 KiB，单次超时 1 秒。字段输出保留提供方的
4096 字节上限；更长、二进制、多值或损坏记录显示明确状态。系统和当前有效
用户的日志有独立边界，不借用 sudo 调用者的身份。

列表按最新在前显示时间、优先级和关系：unit 发出的记录、slice 子成员、
以及管理器或 coredump 消息对 unit 的引用。消息详情保留多行文本，控制字符
被净化；权限受限、截断和无法解析的部分不会冒充没有记录。历史 PID 不链接
到当前进程，以免 PID 复用把旧事件归属给另一任务。

日志文本是应用输出，可能包含地址或其他应用数据；只在显式打开的本地视图
展示，不进入默认 Snapshot、Agent 或硬件报告。这里不对任意日志文本承诺
网络表那样的逐地址掩码。此入口不提供 follow、跨启动查询或日志写入。

日志中按 `s` 查看本次查询的摘要：记录条数、最早/最晚记录时间、优先级分布、
unit 发出/成员/引用关系及不可读条目。`r` 重读，`s` 或 `Esc` 返回原来的日志
列表或消息。摘要只覆盖当前启动中查询返回的最多 100 条，不是全量活动或速率。


### logind 登录会话

Linux 上按 `u` 查看 logind 登记的登录会话。最多读取 128 项；清单和批量
属性查询各有 500 ms、256 KiB 的预算。缺少工具、权限不足、退出或截断
都有明确状态，不用零条会话代替读取失败。启动与普通刷新不执行会话查询。

详情显示 UID、用户、创建时间、PAM 服务、类型、类别、状态、TTY、seat、
远程登录标志、首进程 PID、scope 和空闲提示。空闲提示不是精确的空闲时长。
不查询远端主机、远端用户名或显示地址，也不把会话清单放进默认 JSON。

会话身份包含启动 ID、logind ID、UID 与创建时的单调时间；重新读取时全部
核对。`d` 先重新验证会话，再进入 logind 声明的 `session-<ID>.scope`，
可继续查看控制组或日志；`Esc` 返回会话。scope 没有提供主进程字段时，
保留未知，不把 logind 的 PID 填成 systemd 的读数。`r` 重新读取会话详情。


## 2. SMART / NVMe

### 2.1 设备选择

按下 `s` 后，wtop 会枚举块设备；当有多个设备时，由共享实体选择器呈现，而不是默认检查“第一块磁盘”。选择器支持：

- 用 `↑`/`↓`、`PageUp`/`PageDown`、`Home`/`End` 和鼠标滚轮移动选中项；
- 按 `Enter` 检查选中的设备；
- 按 `Esc` 或 `q` 关闭。

设备来自 `/sys/class/block`，当前上限为 256 条。匹配 `loop*`、`ram*`、`zram*` 或 `fd*` 的分区和虚拟设备会被过滤。剩余设备按名称排序，并映射为 `/dev/<name>`。

目前没有 `smartctl --scan-open`、USB/SAS 桥接的 `-d` 类型探测、手动输入设备路径或多路径去重。因此某些 USB 硬盘盒、RAID 设备、device-mapper 目标或非标准块设备可能缺席，或需要当前不支持的 `smartctl` 参数。

### 2.2 调用与数据

对选中的设备，wtop 运行：

```text
smartctl --json=c --nocheck=standby --all /dev/<device>
```

当前策略为：2 秒超时、4 MiB 输出上限、60 秒结果缓存。`--nocheck=standby` 用于避免主动唤醒处于待机状态的设备。wtop 不会启动 SMART 自检，也不会执行固件、修复或写入操作。

当前解析、并可直接显示在标量区中的字段包括：

- 型号、掩码后的序列号、固件版本、容量、协议、转速和推断出的设备类型；
- SMART 总体通过状态、温度、通电小时数、通电次数和 `smartctl` 退出位掩码；
- NVMe 严重警告、可用备用空间、已用百分比、数据单元、介质错误和非正常关机次数；
- ATA SMART 属性的 ID、名称、归一化值、阈值和原始值以可滚动行显示，上限为覆盖层的 128 条限制。完整结果可能包含比覆盖层所显示更多的条目。

长度超过四个字符的序列号默认只保留后四位，其余以 `*` 代替；更短的序列号则完全掩码。设备类型推断只依据协议、转速或型号/产品文本中的显式 `SSHD` 标记。wtop 不会凭空编造跨厂商的“健康评分”，也没有 SMART 自检历史的专用视图。

缺少 `smartctl`、设备权限不足、超时、输出截断或 JSON 无效，都会返回为不可用（unavailable）、被拒绝（denied）或错误（error）；这些情况永远不会被解释为设备健康状况。

## 3. 内存带宽（实验性）

当前实现是一次性的系统级估算，不是持续的内存带宽监控，也不是内存基准测试。按下 `b` 后执行以下步骤：

1. 在 `/sys/bus/event_source/devices/` 中查找名称以 `uncore_imc`、`amd_df`、`amd_l3`、`hisi_sccl`、`arm_dmc` 或 `dmc` 开头的 PMU。
2. 从每个 PMU 的 `events/` 目录中选取有限的读写事件集合。
3. 通过绝对路径运行一次约 250 ms 的 `perf stat -a -A` 采样，以 `sleep` 作为计时工作负载。
4. 按每个 CPU/uncore 控制器实例在 perf CSV 中的各自运行时长换算速率，再把各实例速率加总为系统级读写 B/s。

选择列表同时提供系统汇总与单个控制器 PMU。系统汇总按所选事件族汇总可用
实例；单项只读取对应 PMU，不会用其他控制器的读数填补没有事件的项。
结果显示测量范围，单项读取前后会核对 PMU 类型，变化或消失时丢弃数值并要求
重新选择。PMU 名称表示内核计数器来源，不代表已确认的 DIMM 或物理通道映射。
全系统内存拓扑的理论带宽只用于系统范围，不作为单个 PMU 的利用率分母。

采样时长内部限定在 50–2000 ms；TUI 默认使用 250 ms。Runner 超时为采样时长加 1250 ms，默认输出上限为 512 KiB。PMU 枚举最多检查 256 个设备和每个设备 512 个 sysfs 事件；单次 `perf` 调用最多使用 64 个受支持的事件。默认运行还要求 `perf` 和 `sleep` 可执行。可靠解析需要 `perf stat` CSV 中的运行时长（runtime），自 perf 4.1 起可用；更旧的格式会安全地返回不可用，而不会用墙钟时间估算。`perf_event_paranoid`、`CAP_PERFMON` 以及内核/平台的事件支持也会影响结果。

只识别以下事件名或模式：

- `data_read`、`data_write`；
- `cas_count_read`、`cas_count_write`；
- 名称中包含 `rdcas`/`wrcas` 或 `cas_count_rd`/`cas_count_wr`。

未知事件不会被猜测为带宽事件。当主机同时暴露 Intel free-running 数据事件和替补的 CAS 事件族时，会选择完整的一族，优先选择完整的 free-running 读写族，并保留该族中每个 PMU/插槽实例。这样可以避免同一份 DRAM 流量被重复计数。同一 PMU、同一方向下编码描述符相同的 sysfs 事件别名也只计一次。`perf` 返回的字节单位按 CSV 单位换算；识别出的无单位 CAS/DRAM 事件按每个计数 64 字节处理。每个被接受的计数行都必须具有有效的正运行时长。运行时长缺失或格式错误会使该行被拒绝，而不会回退到请求的采样时长。

如果仍有有效子集，结果可以成功但质量标记为 `estimated`；如果没有剩余的有效受支持计数，则检查不可用。缺少读或写方向、受支持事件或实例不完整、事件列表截断、多路复用（multiplexing）或缺少运行百分比，都会把成功结果标记为 `estimated`。匹配的 PMU 只证明候选硬件接口存在，并不保证事件受支持或当前用户有权限。启动时的能力探测不会运行 `perf`，因此按下 `b` 后的检查结果才是权威结果。明确的权限错误归类为 `denied`。`perf` 也可能在权限失败后给请求事件追加用户态 `u` 修饰符重试，最后只留下 EINVAL；当 `perf_event_paranoid` 大于 1 且同一条系统调用诊断完整匹配本次请求事件及该修饰符时，该回退同样归类为 `denied`。普通 EINVAL、未知权限上下文或其他事件的错误仍为 `unavailable`，并且仅当有权限上下文等证据支持时才附带 `permission_may_be_required` 提示。默认 TUI 的成功结果上报提供方 `perf_stat`，公式版本为 `perf-stat-csv-no-aggr-v4`。该实现调用的是外部 `perf stat`，而不是直接使用 `perf_event_open`。覆盖层将带宽格式化为 B/s，将利用率格式化为百分比。

只有调用方显式提供有效的 MT/s 速率、整数通道数和整数总线宽度时，才会计算理论带宽：

```text
MT/s × 1,000,000 × (bus_width_bits / 8) × channels
```

默认 TUI 不提供这些拓扑参数，因此通常不显示理论上限或利用率。该实现不会猜测通道数，没有 CPU 家族/型号白名单，没有按插槽/控制器/通道的细分，没有长期历史，平台覆盖也不及厂商参考工具。`perf` 的 CSV 和事件语义还可能随内核/平台变化，因此该功能仍为实验性。

## 4. `sshd` 服务

按下 `D`，或在 Insights 页面按 `Enter`，会让服务检查器执行枚举，产出唯一的 `sshd.service` 单元并检查它。该单元不再作为手工构造的对象提供，因此检查器只检查自己枚举产出的单元。当前实现可以组合：

- 来自 `systemctl show sshd.service` 的白名单字段，如 ActiveState、MainPID、重启次数、退出状态、内存、CPU 时间和 cgroup；
- 进程快照中名为 `sshd` 或 `sshd:*` 的进程；
- `/proc/net/tcp` 和 `/proc/net/tcp6` 中的监听套接字；在没有可用配置提供方时，以端口 22 作为有限的后备。

sshd 专用检查器通过 logind 读取 PAM 服务恰为 `sshd` 的登记会话，显示用户、
TTY、状态和 scope 等元数据。它不是完整的 SSH 连接清单，也不能按 PAM
服务名确定某个守护进程实例；未经过 PAM/logind 的连接不在该来源中。
套接字属主仍依赖调用方提供的证据；该服务的真实 journal
可从通用 unit 详情打开。“不可用”不意味着不存在会话或事件。非 systemd
系统回退到进程和 procfs 监听者证据。

sshd 的 `s` 打开日志摘要，`r` 重新读取，`Esc` 返回服务。来源先核对系统
管理器返回的 canonical unit 与请求名称/别名，再读取当前启动的近期 journal。
权限受限、截断或无效来源保持明确状态，不用零次失败代替查询失败。

摘要对 unit 直接发出、带 OpenSSH 标识的记录匹配认证接受、失败、部分完成、
延后及无效用户等文本格式。计数是匹配的日志条数，不是独立尝试、连接或会话数；
未知格式不猜测，管理器引用不当作认证消息。分类标为估算，查询仍限 100 条、
512 KiB 和 1 秒。不保留用户名、地址、指纹或原始消息，不进入默认 JSON。
记录样本的配置上限只限制 `recent_events`，不改变摘要的查询计数。

配置来自 [OpenSSH 的退出式查询](https://man.openbsd.org/sshd.8)，默认通过
`sshd -G -f /etc/ssh/sshd_config` 展开当前文件、Include 和默认值；旧版本
不支持该模式时使用 `-T`。单次命令限 500 ms、128 KiB，至多两次。
只保留端口、监听地址、认证策略和限制等白名单，不保留主机密钥、命令、
环境变量或原始输出。多条 Port 和 ListenAddress 均保留；读取失败时配置
值为未知，权限拒绝、无效内容和缺少工具有各自原因。

默认详情显示全局配置，不代入某个连接。提供方也接受调用方的
`sshd_connection` 参数，交给 OpenSSH 的 `-C` 应用 Match；部分支持 `-G`
的版本仅在 `-T` 中接受 `-C`，此时保留参数后重试。
连接参数不会保存在检查结果中。两种查询均标为估算并注明当前文件范围：
守护进程可能有启动覆盖项，或尚未重载磁盘上的改动。
来自主机范围 procfs 表、仅按配置端口筛出的监听者也标为估算，
端口相同不能证明该套接字属于 sshd。

进程、监听者、会话、事件和配置都是表格型字段。覆盖层在各自条数下方显示进程、监听者、会话和配置行，每个字段最多 128 条。监听者地址/端口和进程指标在有数据时显示。事件样本保留分类、方法、时间和优先级；摘要从 `s` 展开。systemd 服务的标量字段直接显示。

检查器模型可以在调用方提供会话时掩码远程地址，默认 TUI 上下文启用了掩码：IPv4 只保留前两个字节，IPv6 只保留很短的前缀。该策略只适用于 sshd 检查器。网络页面和 JSON 导出的隐私边界见 [MONITORING.md](MONITORING.md)。

## 5. 能力、权限与失败语义

- `available` 只表示检测到了基本数据源，并不保证设备、权限和事件的组合可用。
- `denied` 表示权限阻止了访问。wtop 不会自动就地提升某个检查器的权限。
- `unavailable` 表示辅助程序、PMU、设备、事件或可选提供方缺失。
- `error` 表示超时、截断、结构化输出无效或其他执行失败。
- SMART 有 60 秒缓存。RAM PMU 和 sshd 的结果目前不缓存，覆盖层关闭后也不会持续采样。

程序默认以普通用户运行。用户可以显式通过直接 `sudo wtop` 或 `--sudo`/`--elevate` 启动整个调用；没有常驻的特权辅助进程，也没有任何会修改系统状态的检查器操作。

## 6. 发布验证与剩余工作

发布验证至少应覆盖：

- SMART：多磁盘选择、无磁盘、列表截断、待机设备、权限不足、辅助程序缺失，以及 ATA/NVMe 测试固件；
- RAM PMU：无 PMU、无受支持事件、缺少 `perf`/`sleep`、权限拒绝、多路复用或单方向结果，以及数值边界；
- sshd：systemd 与非 systemd、默认端口与自定义端口、无进程/监听者、配置 Include/Match 与多端口、旧查询模式、权限拒绝，以及缺少日志/会话提供方；
- 四种 PTY 尺寸下的选中、滚动和关闭路径；
- 确认 `--safe-mode` 下外部命令无法执行。

尚未实现的长期方向包括：通用资源检查器、更多实体/提供方、SMART 桥接参数和自检历史、可信的平台 PMU 映射、更多平台的会话与服务事件统计，以及更完整的逐字段证据和权限说明。
